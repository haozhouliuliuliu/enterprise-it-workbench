# 已知限制

## 1. 范围

- 只使用虚构企业、员工、资产、工单、制度；不连接真实企业系统；
- 执行只发生在项目自己的 SQLite 中（创建工单、预留资产），不实施真实发放/采购；
- 不宣称通过任何企业合规或生产安全认证。

## 2. RAG

1. **混合检索是轻量实现**：hashing embedding（256 维）+ BM25 风格关键词，不依赖神经向量模型；
   对同义改写、跨语言查询的召回有限。
2. **拒答依赖阈值**：无答案问题通过内容词覆盖 + 分数阈值过滤；固定集 9/10 拒答，但边界问题可能误答或误拒。
3. **PDF 文本提取**依赖 pypdf，扫描版 PDF 没有 OCR；复杂版面可能丢失结构。
4. **文档大小上限 2MB**，未实现异步索引；导入在请求内完成。
5. **版本规则是演示规则**：`current + 生效日期` 判断现行；没有审批流来发布制度版本。
6. **未审核/草稿可能出现在检索结果中作为背景**；系统用状态字段与审核提示区分，但模型仍可能误用，
   只能由审核与程序规则降低风险。

## 3. 工作流

1. **提案生成是确定性规则**：动作关键词 + 员工存在 + 部门标准机型 + 库存 + 制度 current + 审核 pass；
   复杂业务（多设备、跨部门、特殊审批链）不在范围内。
2. **审批是单级**：approver 按部门，admin 可跨部门；没有多级会签、代理审批、撤回。
3. **执行动作**只有 `provision_device`（预留一台资产 + 创建工单）；没有采购、发货、资产报废。
4. **并发**是单进程 + SQLite 事务/唯一索引；多副本部署时进程内锁不生效，但数据库约束仍防止重复预留。
5. **重启恢复**只把 running 标记 interrupted，不自动续跑。

## 4. 多 Agent 与模型

1. **模型输出仍是概率性的**：审核 pass 不等于业务绝对正确；
2. 不同供应商的 JSON/工具调用行为有差异，已做修复/降级，但不能保证 100% 结构化；
3. **审核模型（Kimi）限流约 3 RPM**，真实评估耗时较长；
4. 评估中关闭返工以控制总调用次数；返工能力由自动化测试覆盖；
5. **真实评估 8 个场景**，不是统计意义上的质量评估；失败/降级原样保留。

## 5. 安全与部署

1. **静态 Bearer API key**，无 SSO/OIDC、无自动轮换、无 Vault/KMS；
2. **无多租户**；任务隔离按 owner/department，管理员可读全部；
3. **无 WAF/DDoS/审计外送**；日志只在本地 stdout；JSON 日志脱敏但不是不可篡改审计；
4. **本地 HTTPS 使用 Caddy 内部 CA**；生产必须替换受信任证书与主机名；
5. **无生产级备份编排**；备份/恢复是单文件 SQLite 在线 backup，需要运维定时执行；
6. **单节点 SQLite**，无高可用；数据库文件是单点；
7. 页面 API key 只在内存，但浏览器/终端仍可能被恶意扩展读取；生产应使用短期令牌/SSO。

## 6. 测试与评估

1. 112 个自动化测试、覆盖率 84%（刚好达到门槛）；
2. RAG 固定集 30 题（20 可答 + 10 无答案），指标见 testing.md；评估题由作者编写，存在过拟合风险；
3. 真实模型 8 场景，调用 ≤60；失败场景保留，但不代表所有业务路径；
4. 未做性能/压力测试（10 并发仅功能验证），未做长稳测试。
